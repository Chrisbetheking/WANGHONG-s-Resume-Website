Project 01
React TypeScript NestJS Supabase EdgeOne RAG Agent Render

EduAgent | AI + RAG Study-abroad Consulting Workspace

Main personal project: AI application full-stack, RAG retrieval, Agent tool calls, deployment, and observability

This is my main project. It is not just a chat page on top of an LLM API; it is a workspace for study-abroad consulting. The front end handles multi-page flows, forms, collapsible results, export actions, and responsive layouts. The backend handles authentication, model calls, knowledge base, logs, and scoring rules. After an advisor enters a student profile, the system runs a fit assessment and generates school tiers, writing directions, follow-up scripts, and material checklists.

Front-end Workspace React/TypeScript, routing, form state, collapsible results, exports, responsive layout
Backend Service NestJS APIs, JWT auth, guest quota, timeout protection, and backup responses
Data Flow Supabase/PostgreSQL + pgvector for conversations, documents, chunks, and logs
RAG & Agent Knowledge retrieval, tool calls, structured output, and export
Observability Model, latency, RAG hits, tool chain, request IDs, and failure reasons are logged

Front-end and interaction

  • Built a React + TypeScript workspace covering AI consultation, lead content, application dossiers, knowledge base, solution engine, and system logs.
  • Implemented complex forms, select-based configuration, collapsible results, section navigation, copy/export actions, guest access, and mobile layouts.
  • Added front-end state persistence and error boundaries so generated results remain after page switching and one module error does not break the entire page.
  • Iterated information architecture and card layouts so RAG sources, tool calls, scoring results, and writing output can be reviewed clearly.

Backend, algorithm, and output

  • Designed the knowledge-base import and chunking flow, storing documents and chunks in Supabase for later retrieval.
  • Wrapped DeepSeek calls with timeout handling, backup responses, and call logging so model keys are not exposed to the front end.
  • Implemented a weighted-fit scoring algorithm using GPA, major fit, project experience, language score, and budget to produce explainable recommendations.
  • The online version runs through EdgeOne with a Render backend, covering AI consultation, lead content, application dossiers, solution engine, knowledge base, observability, and RAG evaluation.
Front-end talking points Complex forms, page state, collapsible results, navigation, mobile UI, and exports.
Backend talking points Auth, quota, service wrappers, data modeling, logging, and error handling.
AI talking points RAG, prompts, tool chain, scoring rules, and observability.
Implementation boundary: School and application recommendations are used to show the system flow and should still be checked against official university pages. What I want to show here is the engineering chain: business input, retrieval, rules, model calls, logs, and exports working together.

Flutter Campus Shuttle App

A mobile workflow prototype with Student, Driver, and Admin views

This Flutter project is built around a campus transport scenario with shuttle route browsing, OpenStreetMap route playback, parking reservation, passenger check-in, and booking status management. It focuses on mobile information architecture, role switching, and local state flow. The public version uses local demo data and route playback based on real location coordinates, not real GPS tracking.

Implementation

  • Designed role-based entry points for students, drivers, and transport administrators, separating home, route, booking, check-in, and management views.
  • Built booking flows for shuttle seats, parking slot selection, cancellation, check-in, and completed statuses, reusing shared local state across roles.
  • Integrated OpenStreetMap and implemented simulated route playback using local route points and average speed.

Technical focus

  • Built the mobile UI with Flutter, Dart, Material 3, reusable components, page navigation, and responsive layouts.
  • Used shared local state so student bookings also appear in the driver and admin views, simulating real business state transitions.
  • Prepared an online demo, GitHub Pages deployment, and clear implementation-boundary notes for quick review.
Note: This is a portfolio prototype. The map movement is simulated route playback, not real GPS tracking. The app does not use official APU transport data or a production backend.
