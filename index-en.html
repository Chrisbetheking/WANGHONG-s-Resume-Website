Project 01
React TypeScript NestJS Supabase RAG Agent

EduAgent | AI + RAG Study-abroad Consulting Workspace

Personal full-stack project simulating a consulting workflow from lead intake to application materials

EduAgent is the AI application project I am currently maintaining. It is not a simple chat page on top of an LLM API. The system connects student profiles, a knowledge base, scoring rules, Agent tools, and call logs into one workspace: after an advisor enters a student profile, the system runs a fit assessment, then generates school tiers, writing directions, sales follow-up content, and material checklists.

Backend Service NestJS APIs, JWT auth, guest quota, and error fallback
Data Flow Supabase/PostgreSQL for conversations, documents, chunks, and logs
RAG & Agent Knowledge retrieval, tool orchestration, structured output, and export
Observability Model, latency, RAG hits, tool chain, and failure reasons are logged

Core Implementation

  • Built the React + TypeScript front end and NestJS backend, including login, guest mode, API calls, and page state management.
  • Designed the knowledge-base import and chunking flow, storing documents and chunks in Supabase for later retrieval.
  • Wrapped DeepSeek calls with timeout handling, fallback logic, and call logging so model keys are not exposed to the front end.
  • Implemented a weighted-fit scoring algorithm using GPA, major fit, project experience, language score, and budget to produce explainable recommendations.

Output

  • The online demo supports both admin login and guest access, covering AI consultation, lead content, application dossiers, and the solution engine.
  • Generated results can be exported as Markdown or JSON for handoff to advisors, writing support, or sales follow-up.
  • The log page tracks model name, latency, RAG hits, and error details, making slow requests and failed tool calls easier to locate.
  • The project is still being refined, but the main chain already demonstrates backend APIs, database design, RAG, Agent workflow, and productized UI.
Implementation boundary: School and application recommendations in the demo are used to show system behavior and should still be checked against official university pages. The project focuses on engineering flow and business abstraction rather than letting the model make the final decision alone.
