Project 01
React TypeScript NestJS Supabase RAG Agent

EduAgent｜AI + RAG 留学咨询工作台

个人全栈项目，模拟留学机构从线索到申请案卷的业务闭环

这是我目前重点维护的 AI 应用项目。它不是只调模型接口的聊天页面，而是把学生背景、知识库、评分规则、工具链和日志串成一个工作台：顾问输入学生背景后，系统先做适配评分，再生成选校分层、文书方向、销售跟进内容和材料清单。

后端服务 NestJS 接口、JWT 鉴权、访客额度、错误 fallback
数据链路 Supabase/PostgreSQL 保存会话、文档、切片和日志
RAG & Agent 知识库检索、工具编排、结构化生成和导出
工程观测 记录模型、耗时、RAG 命中、工具链和失败原因

我负责的核心实现

  • 搭建 React + TypeScript 前端和 NestJS 后端，完成登录、访客体验、接口请求和页面状态管理。
  • 设计知识库导入与切片流程，将 documents / chunks 写入 Supabase，并在咨询和工具链中作为检索上下文。
  • 封装 DeepSeek 调用、超时处理、fallback 和调用日志，避免前端直接暴露模型 Key。
  • 实现 weighted-fit 适配评分算法，把 GPA、专业匹配、项目经历、语言和预算转成可解释的选校建议。

项目产出

  • 在线 Demo 已部署，支持管理员登录和访客体验，可完整跑通 AI 咨询、客户线索、申请案卷和方案引擎。
  • 系统可以导出 Markdown / JSON，方便把生成结果交给顾问、文书或销售继续处理。
  • 日志页支持查看模型、耗时、RAG 命中和错误信息，便于定位慢请求、失败请求和提示词问题。
  • 项目仍在迭代 UI 和业务规则，但核心链路已经能展示后端、数据库、RAG、Agent 和前端产品化能力。
实现边界： Demo 中的院校和申请建议用于展示系统流程，不替代学校官网要求；真实申请仍需人工核对官网、预算、语言小分和截止日期。这个项目的重点是工程链路和业务抽象，而不是“模型直接给最终答案”。
